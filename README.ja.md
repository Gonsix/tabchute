# TabChute

[English](README.md) | **日本語**

よく使うサイトをまとめて保存し、新しいタブグループとして一度に開く拡張機能です。デスクトップ版のChromeに対応し、Manifest V3・TypeScript・Bunで構築しています。

## ローカルでインストール

```sh
bun install --frozen-lockfile
bun run check
```

1. Chromeなら `chrome://extensions`、Braveなら `brave://extensions` を開きます。
2. **デベロッパーモード**を有効にします。
3. **パッケージ化されていない拡張機能を読み込む**を選び、このプロジェクトの `dist/` フォルダーを指定します。
4. TabChuteをツールバーに固定し、ポップアップから **New group** を選びます。

グループを作成し、色とサイトのURLを登録してください。URLは `https://` または `http://` から始まる完全な形式で入力します。サイトはドラッグ用のつまみ、または上下ボタンで並べ替えられます。保存後に **Open** を押すと、操作したウィンドウに毎回新しいタブグループが作成されます。テンプレートを編集・削除しても、すでに開いているタブには影響しません。

編集画面は専用タブで開きます。変更は **Save group** を押すまで保存されません。別の編集画面で同じテンプレートが変更された場合は、画面を再読み込みして保存済みの内容を取得してから編集してください。未保存の変更がある状態で画面を閉じると、確認が表示されます。

ライト・ダークの配色はOS設定に従います。サイトのファビコンはブラウザ標準のファビコンサービスから取得し、画像がない場合は汎用アイコンを表示します。表示名は任意で、編集画面内でのみ使用します。ブラウザのタブタイトルは変更しません。拡張機能のUIは英語です。

## 開発

```sh
bun run dev        # src/ または static/ の変更時に再ビルド
bun run typecheck  # TypeScriptの型検査
bun test           # モデルとサービスのテスト
bun run build      # dist/ に拡張機能を出力
```

再ビルド後は拡張機能の管理画面でTabChuteを再読み込みし、ポップアップ・編集画面を開き直してください。`dist/` には拡張機能の実行に必要なファイルだけが含まれ、実行時にBunやNodeは不要です。開発用の依存関係は `bun.lock` で固定しています。アイコン画像はGitで管理しており、デザインを変更する場合のみ `python3 scripts/icons.py` で再生成します。

### ブラウザでの統合テスト

```sh
bunx playwright install chromium
bun run test:browser
```

Chrome for Testingと、インストールされている場合はBraveの一時プロファイルで、実際の拡張機能をテストします。編集、入力検証、並べ替え、古い編集内容による上書きの拒否、タブの作成とグループ化、繰り返し起動、操作元の画面を閉じた後の処理完了、既存タブを閉じずにテンプレートを削除できること、ブラウザ再起動後の保存内容を確認します。ライト・ダークのスクリーンショットは `test-results/` に出力します。

Braveが標準の場所にない場合は、環境変数 `BRAVE_PATH` に実行ファイルのパスを指定してください。テストは普段使用しているブラウザのプロファイルには触れません。

ツールバーからの動作は、**Open** を押した直後にポップアップを閉じ、再度開いて手動確認してください。起動結果が表示されること、グループの名前と色が設定されること、グループが展開され先頭のサイトがアクティブになることを確認します。ドラッグ、キーボードでの色選択、フォーカス表示、OSのテーマ切り替えも確認してください。通信エラーやHTTPステータスの扱いはブラウザに任せています。TabChuteが報告するのはタブ作成の失敗であり、サイトが正常に表示できるかどうかは判定しません。

## 構成

- `src/model.ts`：共通の型、URLと保存データの検証。
- `src/service.ts`：テンプレート保存の直列処理、更新競合の検出、バックグラウンドでのタブ起動。ブラウザAPIをアダプターに分離し、テストで差し替えられる構成です。
- `src/background.ts`：拡張機能内のメッセージ処理。Worker起動時に同期的にリスナーを登録します。
- `src/popup.ts` / `src/editor.ts`：DOM操作によるUI。フレームワークや外部配信コードに依存しません。
- `static/`：Manifest、アクセシビリティに配慮したHTML、テーマ共通のCSS、アイコン。
- `scripts/build.ts`：ブラウザ向けES Modulesのビルドと静的ファイルの配置。

テンプレートは `chrome.storage.local` の `tabchuteData` に、`schemaVersion: 1` の形式で保存します。未知のバージョンや不正なデータを検出した場合は、既存のテンプレートを上書きせずエラーを表示します。初回は空の一覧から始まります。元の計画書に記載したJSONは設計案であり、移行対象となる旧実装はありません。

起動処理は最新の1件だけを `chrome.storage.session` に保存します。ブラウザの同じセッション内では、ポップアップを閉じたりWorkerが再起動したりしても結果を確認できます。Workerが予期せず停止した場合は、次の要求時に未完了の処理を中断扱いにし、自動で再実行しません。失敗時も作成済みのタブは残します。ブラウザを再起動すると起動結果は消えますが、テンプレートは残ります。開いていたタブの復元はブラウザの設定に従います。

## 今後のストア配布

同じ `dist/` をChrome Web Store向けにパッケージ化し、ChromeとBraveの両方にインストールできます。リリース前に `package.json` と `static/manifest.json` のバージョンを揃え、検証を実行してから、直下に `manifest.json` が入るZIPを作成してください。Manifestには16・32・48・128pxのアイコンと、拡張機能ページ向けの制限されたCSPを設定しています。

ストア申請には、掲載用の説明文、画像、プライバシーに関する申告、ストアの要件に従った公開プライバシーポリシーURLを別途用意する必要があります。現在のデータと権限の扱いは [PRIVACY.md](PRIVACY.md) を参照してください。このプロジェクトからストアへの申請・公開は行っていません。

初期版はデスクトップの通常ウィンドウを対象とし、データはブラウザ・プロファイルごとにローカル保存します。シークレットモード、クラウド同期、インポート／エクスポート、既存グループの再利用、開くウィンドウの選択には対応していません。
